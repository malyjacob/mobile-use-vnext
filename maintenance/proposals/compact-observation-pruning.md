## 0. 摘要

T2a 省略符合条件的小型无标注图片，包括独立图片，并逐层清理因图片省略而变空的匿名容器。
T2b 按 T2a 之后的直接孩子数绕过单子匿名容器。交互节点、仍有分支的容器和原有空叶保留。
新 compact full/delta 只输出普通节点定义，读取端继续展开旧折叠链。动作规划、重验与详细补看继续读取完整快照。MCP 工具说明给出用原观察编号补看诊断节点的方法。

## 1. 问题

### 1.1 现象与代价

分诊为取舍。现行 compact 契约交付这些逻辑节点，本案调整交付范围。

用户提供的会话含 29 个 full 与 16 个 delta。普通树块共 49,153 个代理 token（`o200k_base`）和 252,724 字节 compact JSON。样本里有一次调用方想点包装层里的按钮，却提交了外层容器编号，按现行向上提升规则点到了更外的交互容器。原始响应、设备内容和截图留在 Git 忽略目录。

### 1.3 为什么直觉会出错

几何标为 `hidden` 也可能只是因为矩形与祖先相同。判定图片面积要看隐藏前的矩形。折叠链的尾节点可能有多个直接孩子，逐个检查逻辑节点才能判断哪些包装可绕过。完整树的几何继续用于计算落点。

## 2. 目标与非目标

- 精简普通观察，保持留存节点的编号、字段、同级顺序和交互节点间的祖先关系。允许节点在后续帧重新出现。
- 保持完整快照及其动作证据。原 O 仍保留时，调用方可按诊断编号补看完整节点及其子树。
- 沿用差分确认基线与大小门槛、`tree v3` / `inspect v3` 语法、坐标编码和详细观察格式。继续接受合法的历史折叠链。

## 3. 路线对比

| 路线 | 做法 | 代价 | 风险 |
| --- | --- | --- | --- |
| R1 沿用现行投影 | 保留图片、包装和折叠链输出 | 沿用现有契约 | 普通树继续交付大量低信息节点，调用方仍可误选包装编号 |
| R2 保留更多原结构 | 只省略最近交互祖先支持点按的图片，T2b 按原孩子数保留分支，继续折链 | 保留更多无名图片线索与原分组编号 | 保留独立小图片和长按控件里的小图片，也会保留裁剪后只挂一个孩子的原分支 |
| R3 按剩余结构精简 | 以图片自身属性与面积决定 T2a，再按剩余孩子数执行 T2b | 共同契约升级，同步差分重建、工具说明与验收 | 部分独立无名图标从普通树消失，原分组可能随孩子数变化而消失或重现 |

选择 R3。无动作的小图片可以按自身条件处理，覆盖独立图片及长按控件内的图片。T2b 保留实际还有多个孩子的分组。调用方可用详细观察查看图形线索。

## 4. 判据

- **T2a 图片省略**。在裁剪前的 compact 逻辑树里，节点须为普通 `image` 叶，几何为 `hidden`，标签和动作列表为空，`value`、`hint`、`resource`、`axis` 均缺席。显式空字符串仍是字段值。`enabled` 已知为 `true`，`focused`、`selected`、`protected`、`checked` 均已知为 `false`。`resource` 按公开投影字段判定。只存在于设备源的 resource-id 不参与判定。
- **T2a 面积**。取完整快照中该图片隐藏前的矩形，按现行规则裁到根节点屏幕矩形。裁后面积为可计算的正数，且严格小于屏幕面积的 1% 时才满足。正好 1%、屏幕面积未知或无效、裁后面积为空或无法计算时均保留。祖先的动作和状态不参与图片判定。
- **T2a 空容器清理**。逐层清理几何为 `hidden` 且满足现行 `AnonymousPlain` 的容器。容器原先至少有一个直接孩子，且因本轮省略图片或清理空容器而变空时才清理。遇到仍有孩子或自身不满足判据的节点就停止向上清理。原有空叶继续保留。
- **T2b 单子包装绕过**。T2a 完成后，几何为 `hidden`、满足现行 `AnonymousPlain` 且恰有一个直接孩子的容器，将唯一留存孩子提升到它在父节点中的原位置。原先挂多个孩子、此时只剩一个的容器也适用。保留仍有两个或更多直接孩子的容器和零孩子的节点。

根、`context`、带动作或有可读信息的节点，以及带未知状态或未知几何的节点保留。所有留存节点沿用裁剪前的公开几何状态。绕过包装时递归处理其后代，遇到交互节点会保留该节点并继续处理其子树。

## 5. 算法

1. 依照基线的几何规则，从完整快照构造 compact 逻辑节点，计算 T2a 所需的面积条件。
2. 自底向上执行 T2a，省略图片并清理因此变空的匿名容器。
3. 对 T2a 的结果执行 T2b，绕过单子匿名包装。保留节点编号、顺序和字段，按最终父子关系输出。在实现中合并遍历时，效果须与先 T2a 后 T2b 一致。
4. 直接交付普通节点定义。现行折叠链须有一个隐藏几何的匿名单子节点作为链头，而 T2b 已绕过这类节点。`add`/`replace` 同样以普通节点定义交付，历史链输入按 §6.1 处理。
5. 观察候选继续接受原有的预算与提交检查。差分不可表示、未确认适用 full 基线，或 delta 大小达到 full 的 70% 时走 full 分支。撤销、超时、预算耗尽与候选提交使用现有处理路径。

以下 `view`/`group` 均假设符合匿名和隐藏几何条件，`小图` 均满足 T2a 的图片判据。`→` 表示父子关系，括号里的逗号分隔同级孩子。

| 场景 | 裁剪前 | T2a 后 | T2b 后 |
| --- | --- | --- | --- |
| 匿名链只挂一张图 | `n7 view → n8 view → n9 view → n10 小图` | 整段消失 | 整段消失 |
| 匿名链尾同时挂图和按钮 | `n7 view → n8 view → n9 view → (n10 小图, n11 按钮)` | `n7 → n8 → n9 → n11` | `n11` 提升到原 `n7` 的位置 |
| 链尾本身可点 | `n7 view → n8 view → n9 可点卡片 → (n10 小图, n11 按钮)` | `n7 → n8 → n9 → n11` | `n9 → n11`，卡片和按钮都可见 |
| 链尾有两个交互分支 | `n12 group → n14 group → (n15 按钮, n16 长按项)` | 原结构 | `n14 → (n15, n16)`，两个文字分支同理 |
| 两个交互节点之间夹包装 | `n20 可点卡片 → n21 view → n22 group → n23 图标按钮 → n24 小图` | `n20 → n21 → n22 → n23` | `n20 → n23`，两个交互节点仍然嵌套 |

## 6. 实现方案

### 6.1 接口与文件

| 文件 | 改动 |
| --- | --- |
| [internal/observation/read.go](../../internal/observation/read.go) | 将两项裁剪用于普通 compact 投影，复用现有面积与匿名判据，取消 compact full 的链打包。详细投影继续交付完整逻辑节点及已知几何。 |
| [internal/observation/read_diff.go](../../internal/observation/read_diff.go) | 差分规划仍比较展开后的树，输出普通 `add`/`replace` 定义。应用器仍接受旧链输入，返回展开的 full。保留逻辑相等和规范 JSON 字节两项校验。 |
| [internal/mcp/schema.go](../../internal/mcp/schema.go) | 在工具注册和握手说明里写清普通树省略规则、按原 O 补看方法及历史 `[n1 n2 …]` 的链尾语义。 |
| [internal/observation](../../internal/observation)、[internal/engine](../../internal/engine)、[internal/mcp](../../internal/mcp) 测试 | 覆盖判据、差分重建、动作证据、历史链读取和实际交付的工具说明，更新工具目录指纹基准测试。 |

`ReadDiff` 先展开 base 与 current，再构造和验证普通节点 delta。应用通过后，将展开结果和展开后的 current 做逻辑比较及规范 JSON 字节比较。对新产物，这组字节就是当前 compact full 的规范 JSON。`ReadApply` 继续验证输入并展开 base 和 `add`/`replace` 中的历史链，然后用结构差分重建普通节点 full。应用阶段只按差分重建树，保留其中的逻辑节点。回放旧数据保证节点、字段、顺序和父子关系可还原，重建结果统一为展开格式，旧折叠字节序列随之改变。链内编号继续可作合法差分引用，旧链下面缩进的孩子归链尾。

例如 §5 第二行的 `n10` 在后续帧变大且原编号继续匹配时，`n10` 会出现。`n9` 因为重新有两个孩子也会出现，`n11` 复用原编号回到 `n9` 下面。直接 full 和对正确已确认基线应用 delta 得到相同的顺序 `n9 → (n10, n11)`。差分仍根据已确认 full 的 O 计算，前一帧如果是 delta，调用方继续使用 `base` 指向的 full。

在 `tools/list` 公布的 `act` 与 `inspect` 说明中给出补看方法。静态错误可能引用普通树中已省略的节点，例如 `error.details.suggested_carrier_ref`。调用 `inspect({reference: 原 act 请求的 O, node: 诊断中的节点编号})` 可查该观察中的详细子树。补看要求同一调用方的原 O 内容仍保留，O 过期后仍可能可读。子树超过预算时返回 `inspection_too_large`。`suggested_carrier_ref` 说明建议坐标的来源。使用 `suggested_point` 重试需原 O 仍 ready、使用新 P 并提交坐标目标，服务端继续独立重验坐标。握手说明同步更新普通节点输出与历史链的读取方式。

## 7. 预期效果与能力边界

### 7.1 能治什么

精简普通观察树，减少调用方可误选的包装编号。既有 45 帧样本在同一批 29 个 full 与 16 个 delta 的比较口径下，前期组合规则的离线分析得到 41,730 个代理 token（−15.10%）与 203,426 字节 compact JSON（−19.51%）。原 compact 样本缺少隐藏前的图片矩形，按本案阈值精确复测需要同帧详细几何。实测记载本案最终 full/delta 分布，因为两种输出的大小会以不同比例变化。

### 7.2 不能治什么

| 现象 | 原因 |
| --- | --- |
| 普通树看不到部分独立无名图标 | 该信息可能来自图像本身。普通树按 §4 省略小图，详细观察保留节点和已知几何。 |
| 大幅切页后经常发 full | 结构差分仍受已确认基线、可表示性与原尺寸门槛约束。 |
| 其他点按误判 | 调用方仍需选对目标，输入继续依赖原有证据与重验。 |

### 7.3 成本

面积检查复用完整快照中的矩形，裁剪是有界的树遍历。设备额外读取和日志为零。调用方需要查看被省略的诊断节点时，可发起一次只读补看。输出减少的字节、代理 token 与投影开销在验证时分别记录。

### 8.2 实机/系统级

精确离线复测使用持有同帧完整几何的样本，记录旧、新策略的节点数、字节、`o200k_base` token、full/delta 分布和逐帧重建结果。若旧样本缺少同帧几何，使用受控页面录制具有匹配详细树的新序列，并单列样本来源。基线样本比较见 §7.1。本案实机验证待实施。

核验手机清单后覆盖整组部署，含手机 MCP，保留 App 私有数据。受控页面覆盖独立小图标、卡片与子按钮、裁后单子路径、分支及可复现的静态拒绝。

1. `start` 取得 ready compact full。使用虚拟屏时，先用 `start` 建立显示，随后在该显示上启动受控页并用 `observe(full=true)` 取得夹具的首个 ready compact full。验证预期图片和包装省略、文字和交互节点保留。对卡片触发一次带承载或歧义 ref 的静态拒绝，核对 `outcome=not_executed`、页面无输入效应，且诊断 ref 缺席于夹具的 compact 树。用同一 O 和同一个诊断 ref 调用 `inspect`，核对详细节点。
2. 保持页面稳定，用 `observe(reference=步骤 1 的 full O, full=false)` 确认基线。断言响应是 delta 且 `base` 指向步骤 1 的 O。随后以这次 `observe` 返回的 ready O 为动作目标，点正常按钮触发小范围结构变化。验证输入确实发生，动作后观察返回非空 delta，`base` 仍指向步骤 1 的 O。受控页面的详细树须在整树补看预算内。收到非空 delta 后，立即对动作后观察的 O 调用整树 `inspect`，从这份同帧详细树离线投影出 compact full，与将 delta 应用到基线所得的拓扑及规范 JSON 比对。
3. `end` 结束会话并记录返回的会话状态与收尾事实。两条独立探针顺序运行，每次启动前在有界窗口检查 `status().can_start`，确认当前准入可用。探针验证发布产物、实际发现的工具说明和正常树交付。

由同一源码提交构建并核验 Windows 清单，替换 `build/device-mcp.exe` 和 `build/mcp-probe.exe`，用哈希和清单确认磁盘替换。用新的独立探针分别验证 Windows stdio 与手机 HTTP MCP，核对握手说明、工具描述、树格式和目录指纹。依赖 Agent、其托管 MCP 进程和重连由用户处理。
