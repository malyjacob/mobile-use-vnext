## 0. 摘要

同一版本交付七项简化。完整结果使用 `result v3`，对观察字段分组。普通树使用 `tree v4`，精简树头，使用无括号矩形、一格缩进、角色默认动作、同矩形引用和同前缀的差分基线简写。0.23.0 的 220 份完整返回离线复算节省 19,202 个代理 token（10.30%）和 106,915 字节（19.09%）。结构化事实可以完整还原。多分支匿名容器另做实机对照，差分继续独立应用到其确认过的整树。

## 1. 问题

### 1.1 现象与代价

分诊为格式取舍。0.23.0 的实机轨迹中，220 份 mobile-use 返回有 560,170 个 UTF-8 字节和 186,456 个 `o200k_base` 代理 token。161 棵普通树消耗 142,511 个代理 token，其中 114 棵整树消耗 128,652。矩形占整树代理 token 的 30.7%。旧文本在每行观察字段重复前缀，并在普通树头重复当前 O。

0.23.0 已在普通树中省略符合条件的小型无标注图片和单子匿名容器。新数据使用裁剪后的节点集合，本文数字衡量在其上的文本简化。原始轨迹、清洗索引和复算脚本保留在本地 `.state/dsh-session-a0d6ab77/research/`。[实机轨迹来源](../../verification/mcp-tool-surface-coverage-0.23.0.md) · [0.23.0 裁剪归档](compact-observation-pruning.md)

### 1.3 节省字节与节省 token 的差异

单独改为一格缩进，节省 55,040 字节和 187 个代理 token。观察字段分组单独节省 17,547 字节和 4,184 个代理 token。实施验收要对完整结果重新分词，按原始 UTF-8 字节另计输出大小。

## 2. 目标与非目标

- 让统一的文本格式交付与结构化结果相同的字段、节点、动作、几何和差分。按同一份结果重复渲染，产出逐字节一致。
- 让调用方直接从 `observation` 分组取得可回传的完整 O，从节点行取得 `n<ref>`，按 `base` 解码观察。
- 保持完整结果结束行、错误分层、图片载体与 JSON 兜底。保留已确认基线、70% JSON 门槛和详细补看契约。
- 本阶段处理文本表达。节点裁剪、真实 O 重编码与宿主历史管理各自取证。

## 3. 路线对比

以下以 220 份完整 mobile-use 返回为分母。组合数字来自逐条重写后的重新分词。

| 路线 | 节省代理 token | 节省 UTF-8 字节 | 代价与失败模式 |
| --- | ---: | ---: | --- |
| R1 沿用现行格式 | 0 | 0 | 客户端维持旧解析，重复字段随动作次数累积。 |
| R2 原草案的最小改动，缩树头和矩形去括号 | 10,291（5.52%） | 25,306（4.52%） | 迁移普通树解析器，结果外层仍逐行重复观察字段。 |
| R3 六项普通树简化，沿用 `result v2` | 15,018（8.05%） | 89,368（15.95%） | 解析器增加默认动作、同矩形和基线简写。观察字段的行前缀仍重复。 |

## 4. 判据

### 4.1 `result v3` 观察字段分组

完整文本统一用 `result v3 is_error=<true|false>` 起始，`end result` 结束，覆盖成功、失败和没有观察的结果。保留现行成员顺序、字面值类型和顶层其他字段的写法。

投影到 `observation.*` 的一段连续字段，写一行无缩进的 `observation`，再把各字段的共同前缀换成一个 ASCII 空格。批内的 `quality.state` 等保留相对子路径。空行、树块或任何顶层行结束当前组。若原成员顺序要求在树块或 JSON 兜底后继续写观察字段，另开一组。解码时合并到同一个观察对象，跨组重复路径、重复树或祖先与子路径冲突按无效文本处理。每组至少有一个字段，根对象 `observation=null` 仍用原标量写法。

`json v1 path="…" value=…` 保留绝对 JSON Pointer 与原值，作为顶层行输出，明确结束当前分组。未知顶层和嵌套成员都沿用这个规则。完整观察 O 来自属于同一结果的 `observation` 组内 `id`，在 JSON 中仍为 `observation.id`。只有可读的合法 O 和通过类型化无损往返的树才能进入 `tree v4`。树无法可读编码时，保留 `json v1 path="/observation/tree" value=…`。

### 4.2 `tree v4` 块头和基线拼写

整树须为 `format=full`、`scope=reported_visible_with_context`、`view=compact`。差分须为 `format=delta`、`view=compact`。块头不再重复当前 O 和固定字段。 `nodes` 是展开历史链后的逻辑节点数，定义行数由正文得出。 `changes` 是五类顶层声明的总量。

```abnf
full-block  = full-head LF LF full-body %s"end tree" LF
delta-block = delta-head LF LF delta-body %s"end tree" LF
full-head   = %s"tree v4 full nodes=" positive
delta-head  = %s"tree v4 delta base=" (full-o / short-base) %s" changes=" natural
full-o      = %s"O" 1*token-char
short-base  = "_" positive
token-char  = %x21 / %x23-3C / %x3E-5B / %x5D-7E
positive    = %x31-39 *DIGIT
natural     = "0" / positive
signed-int  = natural / "-" positive
rectangle   = signed-int 3("," signed-int)
```

`DIGIT`、`LF` 采用核心规则。`full-body` 和 `delta-body` 使用现行节点与差分行语法，并按 §4.3 调整定义行。树头的字段与单空格固定。拒绝额外或重复字段、计数错误、计数或坐标溢出，以及坐标非规范写法。零变化差分头保留 `base` 与 `changes=0`，正文为空。

只有当前 O 和真实 base 都可在最后一个下划线处分出合法的 `O<实例>` 前缀与正十进制序号，而且两者前缀逐字节相同，才将 base 写成 `_<序号>`。实例段必须非空，序号须为引擎可生成范围内的正整数。否则写完整 O。完整 O 沿用公开引用的长度限制。解码器先从整条结果取完整观察 O，再用它的前缀补齐简写 base。缺少 O、简写缺少可拆分的当前 O、尾号非法或重复路径时拒绝该块。一次差分始终独立应用于由该完整 base 标识的整树。`base=_72` 仅用于读树，调用需用适合该工具的完整 O 或 P。

### 4.3 定义行的四项简写

| 项 | 渲染与恢复 |
| --- | --- |
| 一格缩进 | 每层恰好一个 ASCII 空格，树根深度为零。差分的 `+ ` 和 `= ` 只出现在所属定义的根行，标记本身不计入层级。每个定义单独判断缩进和父子归属。 `~`、`-`、`children` 仍是块顶层声明。 |
| 无括号矩形 | 已知矩形写 `l,t,r,b`，允许负数，矩形满足 `right>=left`、`bottom>=top`。未知写 `-`，按策略隐藏的几何省略。角色缺省仍按首列推断，四元组和 `@` 都是几何列。 |
| `@` 同矩形引用 | 普通节点的已知矩形与同一序列化定义中最近一个有已知矩形的严格祖先四边完全一致时写 `@`。沿父链跳过隐藏或未知几何，祖先已解析的 `@` 仍算已知。差分每个 `+`、`=` 子树独立起栈，不从其他定义、base 或前一条结果继承。无可解析祖先时拒绝 `@`。完整历史链定义仍显式写矩形。 |
| 角色默认动作 | 普通 `button` 对应 `tap`，`input` 对应 `text`，`scroll` 对应 `swipe`。若可按当前源动作顺序完整恢复列表，省略默认词。默认动作缺失时保留原有动作并在动作列末尾写对应的 `!tap`、`!text` 或 `!swipe`。若原列表含默认动作而顺序无法按默认插入还原，显式写完整列表。解码时，有显式默认词时保留完整显式顺序，有对应的 `!动作` 时保持原列表，二者均无时先校验其余动作依源顺序排列，再按 `tap, long_press, text, swipe` 的顺序插回默认动作。禁止同一个动作既显式出现又被否定，禁止用其他角色的否定标记。历史链定义继续显式交付动作。 |

差分 `~` 的值语法继续使用现行数组、字符串、状态和三态规则。特别是 `actions=[]` 保持空数组，`bounds=[l,t,r,b]`、`bounds=null`、`bounds=hidden` 各自保留。定义行的默认动作、`@` 和无括号几何不应用到 `~`。普通 `+`、`=` 节点定义使用 v4。 `inspect v3` 仍使用两格缩进、方括号矩形和显式动作词。标签依旧引用为 JSON 字符串，里面的 `@`、`!tap` 或 `_72` 都是文字。

### 4.4 语法与重建示例

```text
result v3 is_error=false
observation
 status=complete
 id=Oabc_72

tree v4 full nodes=3

n1 root 0,0,1080,2400
 n2 group 24,60,144,180 "菜单"
  n4 button @ "设置"
end tree
end result
```

```text
result v3 is_error=false
observation
 status=complete
 id=Oabc_76

tree v4 delta base=_72 changes=3

~ n4 label=["无线设置"]
+ n6 button 24,220,144,300 "返回" !tap
children n1 = [n2 n6]
end tree
end result
```

第一个块中 `n4` 的坐标恢复为 `24,60,144,180`，动作恢复为 `tap`。第二个块应用到 `Oabc_72`，`n6` 显式表示没有 `tap`。如果要对当前观察操作，`reference` 使用完整的 `Oabc_76`。

## 5. 算法

```text
读取同一份公开 Result JSON 和 isError
  压缩文本通道 → result v3
    按原成员顺序投影，连续 observation.* 行组成一组
    observation.tree → 验证所属 O、类型化往返和 v4 可表示性
      合法 → v4 头 → 遍历定义，携带最近已知祖先矩形 → end tree
      其他 → 完整原树值的 json v1
    inspection → inspect v3 或现有 json v1
  完整文本写 end result
  both 的结构化结果、structured 模式和独立图片按现有路径交付
```

投影沿用引擎的实际输出。撤销、超时和观察预算失败继续按各自的事实交付。重验失败附新观察时，带错结果同样按 v3/v4 编码并保留 `is_error=true`。结构化模式的错误文字继续使用 `diagnostic v1`。文本不可表示时在序列化阶段选择完整 JSON 兜底，保持设备调用、租约、O/P 与输入授权边界。

### 6.5 契约与文档影响

本次更改两个独立的 MCP 文本契约。完整文本从 `result v2` 升到 v3，普通树从 `tree v3` 升到 v4。两层按块头分派，现行探针在新产物上以新格式为验收预期。原有 `structured` 可供只接受 JSON 的消费者选择。MCP 入参 schema、`/api/*` 和 `structuredContent` 的共享事实集沿用共同契约 21。工具描述变更纳入工具目录指纹重新生成和核验。[D33](../../decisions.md#d33-mcp-结果模式共享无损事实集) · [版本策略](../../../docs/release.md#2-单一版本源)

## 7. 预期效果与能力边界

### 7.1 能治什么

减少密集整树的几何、缩进、动作词与字段头开销，用分组标签代替重复的观察字段前缀。按已有轨迹重放，返回从 186,456 降至 167,254 个代理 token，从 560,170 降至 453,255 字节。当前 O 和重建所需基线、坐标与动作仍可以精确取得。

### 7.2 不能治什么

| 现象 | 原因 |
| --- | --- |
| 密集页面节点多或分组难读 | 文本缩写保留节点、文字和拓扑，分组裁剪用下一阶段的实机对照决定。 |
| 图片、详细补看占用和 DSH 历史增长 | 图片和补看继续按原内容交付，历史留存由宿主选择。 |
| 跨页面切换时仍返回整树 | 现行 JSON 差分策略继续根据原字节与已确认基线判定。 |

### 7.3 成本

文本消费者一次迁移两层语法，调用说明须能让模型读懂短动作和短 base，字节收益也应在两个入口确认。渲染沿用现有遍历，定义栈额外携带最近已知矩形。兼容旧文本解析器的消费者可选用现有结构化结果。

## 8. 验证计划

### 8.1 单元测试

| 用例 | 期望 |
| --- | --- |
| 结果 v3 与观察组 | 成功、无观察、失败、部分观察和晚于树的字段。核对发现说明中的 O 位于组内，重复或冲突路径被拒绝。未知字段、组间 JSON 兜底和三态能完整回读。 |
| 整树、空差分、非空差分、完整和简写 base | 验证固定头、分隔、计数、树的所属完整 O。同前缀、不同前缀、历史短 O、非法序号和缺失当前 O 均走定义中的路径。对同一 base 的多条差分逐条独立应用。 |
| 缩进、矩形与 `@` | 测试多层、并列、历史链、`+`/`=` 子树、负数、零面积、隐藏和未知几何。覆盖等矩形、差一边、非直属已知祖先、连续 `@`、无已知祖先及跨定义引用。 |
| 默认动作与字面量 | 三种角色各测省略、显式否定与显式完整列表。覆盖其他动作的顺序、错误否定、含 `@` 或 `!tap` 的引号标签。 `~` 的数组、null 和 hidden，以及 `inspect v3` 的显式动作和带括号矩形均按独立语法读取。 |
| 兜底、错误、取消和模式 | 缺失或非法 O、未知成员、不支持的树视图保留 JSON 原值。text/both/structured、图片及取消保持等价性，含已派发动作和失败带新观察。 |
| 调用方说明 | 发现与兼容初始化的图例一致，实际 `tools/list` 带 §6.1 约定的局部提示。核对完整 O、默认动作、`@`、简写 base 和补看差异，使旧版说明或误写的引用示例触发失败。 |
| 反向对照 | 旧外层/树头、错误缩进或错误终止行在新产物验收中失败。合法头与计数下改一个标签、能力、几何或基线尾号，完整双通道比对仍须发现差异。 |

用现有完整测试解码器分别恢复 v3 结果、v4 full/delta 和 v3 补看的实际字段，与同一 `both` 结果的结构化数据逐项对比。独立探针验证版本和语法，完整正文等价由上述解码验证门禁证明。用 0.23.0 的 220 份结果复算 UTF-8 字节和代理 token，记录 161 棵树回读、47 份差分的完整基线等价及格式导致的差异。比较基准是 19,202 token 与 106,915 字节节省，偏差按输出归因。

### 8.2 实机/系统级

1. 从同一实现提交构建手机发布整组和 Windows 工具。用两组清单核验源码提交、共同契约、工具目录指纹、大小和 SHA-256。
2. 手机整组覆盖部署，含手机 HTTP MCP，保留控制 App 私有数据与配对。比对实际运行的手机适配器与清单。替换 Windows `build/device-mcp.exe` 和 `build/mcp-probe.exe` 并核验替换后的文件。
3. 用新产物的独立探针分别验证主机 stdio、手机 HTTP MCP。核对发现/初始化图例、`tools/list` 描述和目录指纹，以及普通结果 v3、普通树 v4、详细补看 v3。
4. 在两个入口分别用 `both` 跑最小受控页闭环。取得一个整树与非空差分，执行一次节点引用动作，补看详情并正常结束。夹具至少命中默认动作和同矩形，取得一对同前缀的 O/base 并验证简写。完整解码私有捕获的文本，对比结构化字段。按同一个完整 base 应用两侧差分，重建后的树逐字段相等。确认完整 O 可以正常用于后续调用。
5. 分别记录手机覆盖、主机磁盘替换、独立进程验证和依赖方切换。依赖 Agent 的托管进程重启、重连与工具重新发现由用户处理。

部署和探针沿用现有构建/核验脚本，私有配置使用当时环境。[0.23.0 实机与独立探针记录](../../verification/compact-observation-pruning.md#5-独立-mcp-探针)
