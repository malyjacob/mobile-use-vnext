## 0. 摘要

[Issue #24](https://github.com/malyjacob/mobile-use-vnext/issues/24) 要减少默认观察树的输出。
保留操作位置，省略无动作的文本坐标、上层已经交付的相同坐标，以及小于屏幕面积 1% 的其余展示矩形。
完整树继续作为动作判断和详细补看的依据。合法差异的 70% 门槛沿用现值。
实施通过审计和发布验证后，推送源码及归档，回帖并关闭 #24。用户自行重连依赖的 Agent。

## 1. 问题

### 1.1 现象与代价

小图标、播放量和卡片内部文字通常随整张卡片一起移动。默认观察逐项交付坐标时，整树会更长，保留同一节点编号的滚动前后对比也可能多出坐标变化。
网易云还有大背景与可点卡片完全重合的情况，中间可以隔着只负责分组的节点。B 站的封面则只占卡片的一部分，封面位置有助于把截图和树对上。

把 §4 的规则离线应用到用户给出的三个当前版单帧。计量区间是 MCP 的 `tree v2` 文本块，含头尾，不含结果头、图片或外层传输。

| 样本 | 有坐标的节点 | 树文本字节数 | 减少 |
| --- | ---: | ---: | ---: |
| X 搜索结果 | 76 → 37 | 4,950 → 4,229 | 721 B（14.6%） |
| 网易云搜索页 | 80 → 34 | 8,107 → 7,213 | 894 B（11.0%） |
| B 站推荐页 | 110 → 44 | 8,233 → 6,951 | 1,282 B（15.6%） |

这些数值来自样本试算。原始树和截图保留在本地私有材料中。B 站样本是 issue 所述滚动后的 full，单帧只能量出 full 的缩减量。要区分基线不足、差分规划失败和超出 70% 三种回退原因，需要成对帧及实际使用的基线。

### 1.3 为什么直觉会出错

只看节点面积会漏掉大型的重复背景，也可能误删小按钮的位置。把面积门槛从 1% 提到 2%，网易云和 B 站样本都没有额外收益。
同样，树变短时差分和整树可能同时变短，最终是否发送差分取决于两者的比例。

## 2. 目标与非目标

- 优先缩短 full 树。可操作节点保留已知位置，展示节点按 §4 筛选，节点编号、内容和父子关系可供调用方使用。
- 允许位置省略状态随画面变化，客户端能从已确认的整树和单份差分重建当前 `compact` 树。
- 完成配套整组发布、独立探针验证与 #24 的远程回帖和关单。
- 变更限于坐标交付，正文预览和标签去重留在 [#25](https://github.com/malyjacob/mobile-use-vnext/issues/25)。Agent 宿主配置和重连由用户处理。

## 3. 路线对比

| 路线 | 做法 | 代价 | 失败模式 |
| --- | --- | --- | --- |
| R1 沿用现状 | 继续只隐藏匿名普通节点的已知坐标 | 无迁移成本，输出维持当前体积 | 文字、小图标及整卡背景继续重复传输坐标 |
| R2 只隐藏装饰图标 | 只处理无动作、无内容的小图标 | 使用风险较低，改动窄 | 漏掉大量文字和大面积重复背景 |
| R3 逐层判断（选择） | 先保护操作位置，再处理纯文字、重复坐标与小区域 | 一部分按位置找文字的任务需要结合截图或补看 | 位置刚好跨门槛时，差分可能反复去掉和补回坐标 |
| R4 只放宽差分门槛 | 合法差异从 70% 试到 85% | 保留所有当前坐标，某些回包更短 | full 体积无收益。延用旧基线可能增加后续回包总量 |

三份样本覆盖了文字多、重复背景多和封面有独立位置的页面。R3 能直接减少单帧输出，同时保住有用的大区域。R4 适合在同段连续滚动有对照数据时单独评估。

## 4. 判据

对组成内部公开树的候选节点，按以下顺序决定 `compact` 坐标。`detailed` 使用完整节点的坐标，未知保持未知。

1. 源矩形缺失时保留未知。根节点和 `actions` 非空的节点保留已知坐标。按钮、输入框和滚动容器由源能力获得动作。角色名本身不构成额外保护，例如只报告可勾选而没有动作的节点继续按后续规则判断。参见 [build.go:341](../../../internal/observation/build.go#L341) 和 [build.go:472](../../../internal/observation/build.go#L472)。
2. 现有 `AnonymousPlain` 节点沿用已知坐标省略规则，面积达到 1% 也省略。无动作的 `text` 同样省坐标。
3. 对剩余展示节点，取父链上最近一个实际交付了矩形的节点。经过坐标隐藏或未知的层级，继续向上找。四个边都相同则省略当前节点的矩形。可见矩形不同，即使重叠很多，也进入下一条。
4. 以合成根的矩形面积为分母，用完整树中已裁剪到目标屏幕的节点矩形计算面积。低于 1% 则省略，恰好 1% 或更大则交付。使用整数计算并防溢出。屏幕面积无法可靠计算时跳过此项，保留经过前面规则后仍可交付的坐标。

动作列表、根或文字角色、现有匿名判据、坐标与祖先关系用于判断。标签、资源提示、选中、聚焦等字段照常传递。普通 `view` 上有标签仍按展示节点规则处理。只有旧有 `AnonymousPlain` 节点进入折链判据，文本或图片因为新规则隐藏坐标时仍作为独立节点交付。

## 5. 算法

```text
采集 → 构造带完整坐标的内部候选
     → 从合成根向下投影 compact，沿路径传递最近的已交付矩形
     → 以现有规则折链并编码 full，按现行预算检查
     → 有效基线时计算差分并回放验算
     → 复验会话、工作、显示、STOP 与期限后提交 full 或 delta
```

遍历每个节点时复制公开字段并按 §4 确定坐标状态。已知且交付的矩形成为子节点的新参考。隐藏或未知坐标的节点向子节点传递原有参考。`inspect` 走原来的详细投影。
在 full、add 和 replace 的节点定义里，隐藏体现为省略 `bounds`。在 set 里，从交付转为隐藏用 `bounds:"hidden"`，恢复时发送四整数数组，变为未知时发送 `null`。没有更新则省略 set 字段。

公共 full 超限、完整快照超限和留存超限由原预算分支报告。差分不可表示、回放不符或编码超比时交付符合预算的 full。候选阶段在状态锁外工作。撤销、超时、换屏和工作归属变更由既有发布门禁拒绝不再有效的候选。

## 7. 预期效果与能力边界

### 7.1 能治什么

减少默认整树的坐标输出。滚动中仍被省略的矩形平移无需作为坐标变化再发。调用方能根据保留的控件和卡片位置选目标，必要时从保留的历史 O 补看节点。

### 7.2 不能治什么

| 现象 | 原因 |
| --- | --- |
| 滚动后仍发 full | 基线、节点连续性和差分成本各自会影响选择。保留坐标的节点仍会移动 |
| 树很大或宿主仍截断 | 树大小还受节点数量、文字和宿主上限影响 |
| X 的「显示更多」缺独立点位 | 树把它合在正文里。详细补看能取得正文节点的矩形，无法给出正文内部蓝字的精确区域 |
| 历史 O 已淘汰、补看内容超预算 | `inspect` 受原留存和大小限制 |

### 7.3 成本

默认投影本来就遍历整棵树。沿路径维护一个最近已交付矩形，不回扫祖先列表。新增工作为每个展示节点的矩形比较和整数面积检查。没有额外采集。位置敏感的调用可能需要一次 `inspect`。

## 8. 验证计划

### 8.1 单元测试

| 用例 | 期望 |
| --- | --- |
| 功能节点、纯文字与未知字段 | 小而可点的节点保有坐标。只有控件角色、没有动作的节点仍按面积或重复规则判断。大小不同的无动作文字都隐藏。源坐标未知时仍编码为未知，状态字段三态可还原 |
| 面积边界 | 小于、等于、大于 1%。越屏节点的原矩形大于 1%，在屏部分恰为 1% 时保留，再向外移动后省略。换屏重新计算。重复判据同样使用裁剪后的矩形。投影前后内部树内容相等 |
| 重复矩形 | 覆盖直接重复、隔着坐标未知或隐藏的分组层、最近曾交付的上层位置不同。重复判据要求四条边完全相等，保留有独立位置的大封面。有动作的节点即使完全重合也交付 |
| 反向对照 | 去掉文字、重复或面积判据时，相应测试须失败。去掉操作位置保护时，微小按钮用例须失败 |
| 完整树与差分 | 详细投影拿回原坐标。已知、隐藏、未知的至少各向转换通过 JSON 与 MCP 文本往返。跨门槛和跨上层移动时能从同一 full 基线正确重建。仍隐藏的平移不单独产生坐标更新 |
| 折链与预算 | 新隐藏的文本和图片不折链，既有合法链可还原。公开预算测 `compact`，内部预算测完整快照。超限和差分回退按现行规则 |

### 8.2 实机/系统级

1. 在同一帧上比较旧新投影。三份附件离线回放时，逐个节点比对 §4 所得的隐藏集合、坐标值、动作和树结构，坐标数精确达到 §1.2 的 `37 / 34 / 44`。MCP 文本上限依次为 `4,229 / 7,213 / 6,951 B`。附件的树为 MCP 文本。HTTP 验收使用同一合成夹具的旧版规范 JSON 作为基准，新版长度上限为基准长度减去预期省略字段（含分隔逗号）的实际编码长度之和，并要求解码后只有预期坐标状态变化。样本原始内容留在本地，实机另记实际结果。
2. 在虚拟屏使用现有受控测试界面，验证一次轻量操作能走通。核对小按钮和卡片能定位，文字仍归在正确卡片下，`inspect` 能补回隐藏的原坐标。代表性页面可重访时补充对照，比如记录 X「显示更多」在有图与只看树时的定位差异。
3. 取得含确认基线的连续滚动序列，用同样的帧按 70% 与 85% 重放。每种门槛按照自身 full 的后续确认更新基线。比较 full 次数、累计发送字节、差分与 full 大小和保留的 ref 数。逐帧在回放中区分请求强制 full、无适用基线、差分构造或回放失败、编码失败、超出比例。85% 的结果作为是否另调门槛的证据。
4. 发布后核对手机 APK 版本、服务与实际手机 MCP 进程镜像、App 配对、当前恢复、`can_start` 和 STOP。使用新 Windows 产物启动独立 stdio 探针，并连接手机 HTTP MCP 分别跑 `smoke`。核对工具列表、清单身份及最小观察与结束闭环，验证新树说明可通过发现取得。

## 10. 实施顺序

1. 按 `maintenance/process.md` 完成提案独立只读审查，交项目负责人确认。确认后重新核对基线，按 §4 实现和测试。配置 Go 1.27 与 `GOEXPERIMENT=jsonv2`，运行相关 Go 包的回归、版本生成检查和 linux/arm64 交叉构建。
2. 同步正式文档，启动独立只读文档审计。审计期间保持送审的 `docs/` 文件稳定，收到结论后修订并复检。按审计结论落实现提交，提案在该提交中使用「提案，未实现」。
3. 在已提交的干净树上构建、核验两组清单。以下命令均为执行阶段的计划命令。

   ```powershell
   ./scripts/build-release.ps1
   ./scripts/verify-manifest.ps1 -Manifest build/release/manifest.json
   ./scripts/build-host-tools.ps1
   ./scripts/build-host-tools.ps1 -VerifyOnly
   ```

   手机和主机清单应对应同一构建提交、共同契约、发行号及工具目录。主机脚本按文件替换
   `build/device-mcp.exe` 与 `build/mcp-probe.exe`，核对实际采用的镜像路径和两份哈希。
   只停本次维护的独立进程。依赖 Agent 及其托管进程由用户负责。若旧进程仍在执行旧映像，照实记录脚本保留旧映像的情况。用新路径启动独立探针证明新二进制可用。
4. 进入手机部署窗口，沿用既有设备、配对、回环端口和 Origin 配置。按发布手册暂停新工作，使用旧服务结束活动会话或 STOP，等待至多 5 秒逻辑交接。随后用 `./scripts/deploy.ps1 -SkipBuild` 默认安装并启动手机 MCP，按现有部署配置传入必要参数。脚本复验清单、覆盖安装 App、保留私有数据、验证部署文件。按 §8 分别验证手机入口、主机新产物和当前恢复与收尾。失败时沿用 [发布回退边界](../../../docs/release.md#5-失败与回退)。
5. 同一构建提交上完成清单复验后归档。按模板在归档头写实际实现 hash，移动提案、重写并核对相对链接，补 §11 的落点与偏差理由。提交验证记录，有实测或未验证状态变化时一并更新 [maintenance/status.md](../../status.md)，没有变化则在记录中说明。获取远端状态，按 §9.1 核对实际待推提交和目标，快进推送并确认远端包含实现及归档提交。提交用 `Refs #24` 关联，关单在下步执行。
6. 在 GitHub #24 发布结果，包含远端提交链接、实际版本、验证摘要和发布边界。读回确认回复可见，再用 `completed` 关闭并读回核对。关闭的前提是要求的发布与验证已通过，且源码和记录已推到远端。
