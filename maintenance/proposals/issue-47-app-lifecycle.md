# 提案：允许 app 分支冗余入参，按会话归属强停 Android 用户下的应用包

状态：提案，未实现。
基线提交：`d65c97653adb262e750b1e8879e1937a3b8035d7`（分支 `master`，2026-11-25）。
适用范围：HTTP、MCP、强类型客户端的 app 工具；虚屏任务和包的生命周期。
影响范围：internal/{protocol,engine,device,android,client,mcp}、探针、release、docs。
契约（`/api/*` 字段与 `contract_version`）：改变。以 30 为基线升至 31。

实现前重核 HEAD，重点检查 app 请求、任务归属、迁移和操作结果。需求见 [Issue #47](https://github.com/malyjacob/mobile-use-vnext/issues/47)。

## 0. 摘要

分诊为契约取舍。#47 原文建议保留既有边界；维护者在后续讨论中明确扩大了 kill 的作用范围并选择宽容分支冗余。回复 issue 时须说明这一契约迁移。允许调用方复用 app 参数对象，公布七个分支的有效字段。
close 负责窗口，kill 对指定 Android 用户的一整个包执行一次强停。
本会话明确关闭自有窗口后仍可按包名发起 kill。引擎分别报告派发、任务、进程及观察事实。

## 1. 问题

### 1.1 现象与代价

Issue 报告 find 多带 reference 和 list 漏传 reference 都得 422；原任务消失后仍可能有后台进程。现有调用方还需自行拼接事实决定是否已达到目的。

### 1.2 证据链

- docs/interface.md:1498 与 internal/protocol/surface.go:284 的分支矩阵一致。surface.go:259 的共享解码尾部会复制多个许可开关，放宽字段时须同步收窄复制。
- internal/engine/app_close.go:205 冻结 live 目标；internal/engine/app_kill.go:46 按 task 查找，:275 检查自有任务及同包窗口。关闭最后的窗口后原入口无法定位。
- internal/engine/app_kill.go:128 的进程后验早于窗口收尾；internal/mcp/result_text.go:1160 展示分项，无法据此证明最终采样时的包状态。

### 1.3 为什么直觉会出错

task ID 可复用，包名也只标识对象。历史选择器无法证明当前仍有权停止一个包。新实例出现、窗口存在、用户看到界面分别需要独立证据。

## 2. 目标与非目标

支持前台自有窗口直接强停、同会话独占多个窗口整体强停、close 后按包强停。保留主屏会话限制、控制 App 保护、服务与播放门禁。范围限当前会话和已核实 Android 用户；排除跨用户停止、无限追杀、保证未来冷启动及推断用户感知。

## 3. 路线对比

|路线|做法|代价及失败模式|
|---|---|---|
|仅改工具说明和投影|解释字段和 PID|兼容性最好，close 后仍不可定位|
|仅在 live task 上做包级强停|复用任务选择与归属|少维护历史状态，漏掉关窗后停止后台的需求|
|采用：分支归一化、包级强停、会话内短期归属|增加关闭后定位和收尾核验|需管理授权失效，联合升级客户端|

## 4. 判据

顶层按 app 字段全集检查名称、类型、重复、大小写、null 和单一 JSON 值；对象内未知键及类型也严格检查。仅对生效字段执行分支值域、引用查找、选择器互斥及权限处理；冗余字段不进入归一化请求。生效 target 恰选一种选择器。list 漏 reference 的报错点名分支和字段。

|kind|必填（另均需 kind）|生效选项|消费 ready O|
|---|---|---|---|
|find|无|query|否|
|list|活动会话 O/P reference|scope、app|否|
|open|reference、target.app|无|是|
|claim|reference、target|无|是|
|handoff|reference、target|restore_foreground|是|
|close|reference、target|allow_borrowed|是|
|kill|reference、target.task_id 或 target.app|allow_stop_playback|是|

kill 的 task 入口要求实时精确匹配；包入口要求有当前自有任务或本会话确认关闭自有任务留下的资格。两种入口均须证明全部同包 live 任务都归当前会话自有，且没有受保护的转移责任。空任务集仅允许凭关闭资格进入。未知归属、设备身份或任务枚举不完整均拒绝。

## 5. 算法

1. 在 engine 按会话代次、设备 boot、Android 用户、包及安装身份绑定关闭资格。close 逐项确认窗口移除时，在归属仍有效的同一状态提交中把 owned 记录转换为资格；borrowed、未确认移除、旧会话迟到结果均不能建立资格。recents 单独记账。
2. handoff 或在变更操作重验中发现外部使用、安装身份变化时撤销对应资格；会话撤权、显示代次失效、进程重启时清除。历史 task ID 不作授权入口。find/list 始终只读。从确认关闭起按单调时钟保留 5 分钟（供调用方短程收尾），查询不续期，到期按 kill_not_owned 拒绝。内存记录按包合并，最多 64 包，满时淘汰最早资格，调用方再次按包请求时以归属不足拒绝。
3. 取得普通工作位置，锁外取完整任务、用户/安装身份、进程、前台服务、播放和 root 证据；复用既有保护和错误分类。保护状态未知即拒绝，即使显式允许中断播放。拒绝发生在认领前则 O 可用。
4. 认领 O 后，派发前重验原会话、期限、归属、权限、任务快照及设备身份；变化则已消费、未执行。仅向已验证用户和包派发一次 force-stop；STOP 立即撤权，禁止后续派发，已经派发的命令可能完成。系统外部状态变化与设备命令之间存在竞态。
5. 在工作期限内有界读取最终同包任务、进程及实例身份；独立记录命令回执。未派发为 not_executed，派发且完成证据不足为 uncertain，确认命令完成为 executed；后验未知不能覆盖已知派发事实。无循环补杀。仅按证据及原代次提交归属清理；确认强停后消费历史资格，未知回执封闭旧资格，原 P 保留事实供 status 查询。

## 6. 实现方案

### 6.1 接口与文件

|位置|改动|
|---|---|
|internal/protocol、internal/client|统一 HTTP/MCP 接入语义、选择器、可选结果字段与三态解码|
|internal/engine|关闭资格与失效、两种定位入口、单工作单派发、结果推导|
|internal/device、internal/android|按用户和精确包名强停，读取身份、任务、进程，区分派发回执|
|internal/mcp、探针|工具目录公布矩阵，按任务/归属/进程展示结果，覆盖 HTTP 与 stdio|

### 6.2 配置与取值

沿用操作期限与撤权交接预算；不增加用户可调开关。复用 allow_stop_playback，绝不从其他分支继承。从任务清单解析 android_user_id；PackageProcesses.UserID 目前承载 app_uid，不得用作命令用户参数。拟从 PackageManager 核对指定用户安装状态、应用 UID、首次安装时间和签名；来源不可靠即拒绝。测试覆盖相同包跨用户、重装及资格超时。只在 release/versions.json 手改版本。

### 6.3 日志与可观测性

沿用白名单事件；包名、命令、设备输出均不新增到日志。面向调用方的证据进入结构化响应。

### 6.4 与既有不变式的关系

|不变式|约束|
|---|---|
|唯一权威、短锁|资格仅在 engine 内存保存；设备读取在锁外|
|O/P 和 STOP|静态拒绝不认领；认领后不归还；同 P 不重发；STOP 不等后验|
|条件提交|旧工作不能写新会话状态；后观察失败保留已证实的执行事实|

### 6.5 契约与文档影响

同步 docs/interface.md、docs/mcp.md、相关架构和发布说明。kill 返回包及用户、已知目标任务 ID、最终剩余任务 ID；集合完整且为空才给空数组，未知则省略。保留可证的原实例和最终 PID 统计，restarted 在不可比较时显式 null；无源任务时省略源 task 字段。移除契约 30 对空原进程集预填最终结论的规则。包级采样结果枚举 stopped_at_check（完整任务和进程均空）、still_present（任一证实存在）、unknown。claim/handoff 投影实际任务、显示屏、归属和状态保留证据；close 展示逐项移除及 recents。不从 PID 推导界面可见性。四分支 MCP 摘要统一按执行、任务/归属、进程、前台观察顺序投影；注明前台服务证据的阶段，未采样明确显示未知，无需为统一展示额外扫描设备。tools/list 固定断言七行矩阵，list 缺参断言 details.field=reference 和具名文案；仅复用既有 field，不引入 allowed_fields 等元数据。沿用现有错误码分类；逐项核查 status、client、probe 和协议生成物。

## 7. 预期效果与能力边界

### 7.1 能治什么

调用方可重用参数，能分辨关窗、交还和强停，并在关窗后明确请求停止后台。

### 7.2 不能治什么（必须写）

|现象|原因|
|---|---|
|之后用户重新启动应用|只证明本次采样|
|旧号码、已失效资格或未知归属不能强停|防止影响后来使用该包的人|
|进程存在却无法判断用户是否看得见|界面、服务与进程证据不同|

### 7.3 成本

kill 增加派发前身份重验和派发后的任务/进程读取，调用者承担工作期限内的延迟；内存按会话有界，实测耗时记入验证记录。

## 8. 验证计划

### 8.1 单元测试

|用例|期望|
|---|---|
|find 带过期 reference；list 漏 reference；错误类型/未知键|分别成功、具名 422、严格拒绝|
|其他 kind 带许可开关|归一化后不传入引擎；O/P 与无冗余请求一致|
|前景、多自有窗口、关闭最后一个 owned 后按包 kill|均只派发一次包级命令；回退基线时最后一例必须失败|
|借入后关闭、外屏重开、用户切换、重装、资格淘汰、handoff|拒绝；不向错误身份派发|
|临近到期执行 find/list 后越过 5 分钟|不续期；即使包仍无窗口，历史资格已失效|
|close、claim、handoff、kill 的已知、未知与省略字段|MCP 逐层投影同一份 HTTP 事实，无证据时不显示成功结论|
|STOP、重验竞争、后验读失败、任务残留及新进程|无二次派发或迟到提交，命令与两类后验可区分|

### 8.2 实机/系统级

主代理集中运行全量测试，引擎单次命令超时 15 分钟。核验 release manifest 后手机整组覆盖部署（含手机 MCP，保留 App 私有数据）。使用专用可停止应用，分别实测虚屏前台强停、close 后按包停止仍运行的后台、用户主屏重开时拒绝。核对返回值与独立设备采样，注明采样时点。用同一源码提交构建替换 Windows build/device-mcp.exe、build/mcp-probe.exe，核验主机清单，以新探针分别测主机 stdio 和手机 HTTP MCP。依赖 Agent 重连由用户处理。
